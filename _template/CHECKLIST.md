# Checklist

Problemi e miglioramenti trovati lavorando (`core.md` §6.22). Non interrompono il lavoro in corso: si analizzano in un secondo momento, insieme all'utente.

Formato: una voce per riga, con casella `[ ]` (aperta) o `[x]` (chiusa). Ogni voce dice cosa non va, dove e, se noto, perché. Le voci chiuse non si cancellano: restano come traccia.

## Aperte

- [ ] Descrizione del problema — file o passo in cui è emerso (es. `src/Api/Orders/OrderEndpoints.cs`)

## Chiuse

- [x] Esempio di voce chiusa — esito o commit che la risolve
